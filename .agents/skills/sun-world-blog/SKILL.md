# Sun World 迭代博客

每次完成有独立阅读价值的 Sun World 迭代时，为读者整理一篇中文图文文章。连续修订同一主题时优先更新已有稿件或文章。可以把只有零星改动的批次合入下一篇。用项目记录、实际改动和验证结果作依据，明确区分设计、已实现、已验证和已上线。只取适合公开的内容。

1. **选题与稿件**。先查 `docs/blog/` 和站内同题文章。写清读者遇到的问题、这次具体做法、一个可理解的例子，以及目前验证到哪一步。把 Markdown 源稿存入 `docs/blog/YYYY-MM-DD-<slug>.md`，正文首行使用一级标题。
2. **分类和标签**。以文章的主内容选择一个已有分类，例如界面和交互归「前端」，服务、数据、权限和 Agent 运行归「后端」。从站内标签中复用最贴切的 2–4 个技术或主题词。同系列沿用同一系列标签，避免同义或大小写不同的重复标签。确有缺口时才添加标签。
3. **图文结合**。每篇至少有一张帮助读者理解的正文图。流程和架构优先用依据代码绘制的图，体验变化优先用已脱敏的实测截图或前后对比图。照片和概念插画可使用适合的图片生成工具。把图放在相关段落旁，加描述性替代文本和必要图注，检查手机宽度下是否可读。本地稿件和原图可放在 `docs/blog/assets/`，发布时用可匿名访问的 HTTPS 图片链接。
4. **发布与回读**。用户已授权且可通过正常方式取得有权限的 API 会话时，按 [发布参考](references/publishing.md) 走 Sun World 博客 API。发布前检查同题和同标题记录。成功后用公开接口回读，并确认站内链接、分类、标签与正文图可见。授权、会话或图片公开访问条件不足时，保存带图稿件和拟用分类、标签，记录缺的条件，继续交付其他已授权的工作。
5. **记账**。在对应 handoff 记录稿件、所用分类和标签、发布状态。发布完成后补文章链接。同一个话题的修订使用原文章 ID。专题记录随项目迭代维护。
