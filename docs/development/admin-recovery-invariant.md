# 管理员撤权的事务边界

本轮延续阶段 A 的账号恢复要求，只保护现有管理写入不把启用管理员清零。保留 `require_admin`，不新增授权入口、Agent 写能力或数据库外恢复通道。管理员仍按 `status = 1` 且角色代码 Python `str(code).strip().lower() == 'admin'` 判定；这不证明账号具备可用凭据或人工恢复路径。

## 写入契约

- UserManager 的 status 更新（含 delete_user 逻辑停用）、角色替换，RoleManager 的 code 更新、角色删除，统一使用单连接 READ COMMITTED unit of work。
- 事务先按 roles 主键顺序锁住现存角色行，再写入，提交前再次锁读角色目录并检查至少一个启用用户绑定规范化 admin 角色。没有管理员时拒绝会清零的维护；修复性写入只要最终产生至少一个启用管理员即可提交。普通资料/密码更新、角色名称描述更新不减少管理员，保留原路径。
- 锁用于串行化本服务的撤权路径，不依赖进程内锁、SQL TRIM 或事务外 COUNT。空目录无法构成管理员，最终检查拒绝提交；并发新建角色只能增加候选，最终计数使用已锁住的目录。锁等待/死锁/SQL 错误按失败回滚，不自动重试或提交部分结果。
- 角色替换先验证目标用户与全部角色存在、去重后整体替换；任何插入失败回滚原绑定。角色删除同步删除 user_roles 与 role_resources，三者共用事务。
- 最后管理员保护错误使用固定 `AUTH_LAST_ADMINISTRATOR` 和中文消息；现有 user DELETE、role PUT/DELETE 映射 HTTP 409，响应不包含账号/角色身份。未新增用户更新或角色分配 HTTP 路由。

## 验证与边界

先记录原源码行为，再由独立 owned/socket-only MySQL 创建随机库和合成账号，验证四种撤权、角色清理、重复规范化角色、多个管理员、禁用账号不计数、失败回滚、并发及连接池大小1。用真实两连接交错证明后到撤权等待并在前一事务提交后重新判断，不以 mock 串行执行代替并发验收。

还须检查 HTTP 409/原管理员守卫，运行完整 API 门禁并只读复审。证据绑定源码文件 SHA 与 source-only tree，记录临时实例身份和清理结果。没有改动生产表或业务库。

本保护依赖所有减少管理员的写入经过该协议；外部 SQL、旧版本服务和人工库操作不受保护。角色锁是当前小目录的保守实现，大规模目录应先评估锁范围。近期认证、细粒度可授予能力、审计、目标环境盘点与真实恢复演练仍待，不将此轮称为阶段 A 完成。

本轮不新增代理配置；只复用现有 Clash Verge，不恢复已停止的官方模型付费采样。交接 Claude Code / claude-ds 时须传递上述事务与范围约束。
