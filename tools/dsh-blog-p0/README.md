# dsh 只读博客问答 P0

在装有 Node 24.17.0 和 Corepack 的 macOS 上，从仓库根目录运行：

```sh
./tools/dsh-blog-p0/run-local.sh
# 也可只验证主链路
./tools/dsh-blog-p0/run-local.sh normal
```

脚本在临时目录按独立锁文件安装 dsh 0.2.2-rc.1，并禁用安装脚本。依赖下载使用包仓库。运行阶段通过 macOS `sandbox-exec` 限制为回环网络，并阻止读取用户主目录，给 Node 安装目录留出只读例外。每次用例启动独立 SDK 子进程，使用新的 `DSH_HOME`、工作目录和临时运行凭证。脚本结束后移除临时目录。需要真实隔离边界的下一阶段应使用独立容器或虚拟机。

显式 profile 只把 `blog_search_public`、`blog_read_public` 两个工具暴露给模型。两项工具调用受保护的本地网关。检索只返回已公开的标题，读取只返回已公开正文。固定的应用级问答说明从 `blog-qa.md` 注入。SDK 通过 `session/prompt` 直接提交文本，避免将用户提问解释成原生命令。模型端点模拟 DeepSeek Messages 流式响应，并逐次校验 dsh 传回的工具结果，包含跨帧工具参数。

用例覆盖正常问答、跨运行状态隔离、斜杠开头提问、空检索、未发布正文、未注册工具、伪造引用、模型截断、超时和主动取消。只接受成功终态，再从已实际读取的公开 ID 生成引用。示例链接使用保留域名 `blog.example.invalid`。每行 JSON 记录一个用例及耗时，`time -l` 输出运行命令的资源样本。

本原型使用固定文章和可重复的模拟模型响应。要验证模型实际选择工具的效果，需要另一个经批准的 Messages 兼容真实模型和相应出站边界。P0 使用的进程与网络限制、权限凭证和引用数据均服务于本地验证。
